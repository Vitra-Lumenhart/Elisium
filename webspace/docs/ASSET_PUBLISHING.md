# Webspace asset chain — acquisition, transformation, publication

Status: RFC only. This document does not claim assets were downloaded.

## Separate four concerns

- Research source: Poly Haven, museum CAD, scanned reference, artist contribution, own procedural generator.
- Editable master: STEP, BLEND, source texture, geometry generators, original photo source.
- Runtime asset: optimized GLB/glTF + WebP/PNG + LOD, stable hash, transform/units and verified material support.
- Gallery: preview renders, proposal discussions, ratings/reactions, issue linkage, provenance and download URL.

One venue does not have to provide all four. Poly Haven is our third-party DOWNLOAD library, not the upload API for Vitra's generated work. Its current contributor policy forbids generative-AI use in submitted assets. Use its public documented API for list/info/files; never scrape the site. Model downloads require a descriptive User-Agent, correct source recording and a visible Poly Haven credit if the live API is part of the product.

Do not mark AI or procedurally produced art CC0 solely because it was generated by Vitra; confirm authorship, inputs, rights and permission to release. Original code may use MIT with proper ownership; distinguish licensed third-party assets and fan-fiction source IP.

## Poly Haven acquisition

1. GET api.polyhaven.com/search, /info/{id}, /files/{id} with an identifying User-Agent; display a Poly Haven credit if using the live API for public browsing.
2. Select needed model format/resolution and all dependent textures.
3. Download deterministically, verify upstream MD5 and record origin/author/license.
4. Convert and optimize locally in Blender or an audited pipeline; save source and derived hashes.
5. Export LODs and full glTF transform/material metadata. Run mesh/material compatibility tests against the actual Webspace renderer.
6. Publish tiny runtime assets to Pages, larger artifacts to stable versioned object storage (CORS and cache headers verified), and the provenance manifest to Git.

A direct dl.polyhaven.org URL might technically load, but stability, caching, source CORS, file sizes and future third-party rate/policy changes make it an unsuitable default production dependency. Browser CORS/headless WebGL fetch behavior must be tested before using any such URL.

## Comments and ratings

GitHub Issues for individual asset bugs; Discussions and polls for curation; PR reviews for improvements; GitHub reactions as informal votes. GitHub does not directly expose native anonymous asset ratings as a static Pages feature; a public ratings system needs moderation and a separate API/database or third-party service.

Google Drive is a convenient private collaboration, staging or backup layer, not a content-addressed publication CDN. Avoid hotlinking share URLs in WebGL asset manifests.

## Delivery budget

Track bytes, triangles, draw calls, materials, textures, transmittance and load time. Prefer one model with instances over copies, compressed textures, quantization and selective external loading. Include a lowest-fidelity fallback and a phone/GPU-restricted preview. Asset sizes are budgets, not artistic truth.

## v6: deliberate live-versus-frozen asset modes

The Kilns now has an **on-demand live** official-API glTF source inspector (assets/kilns/polyhaven-live-viewer.mjs). It checks the current upstream /files/{slug} list when a visitor asks to see an item, follows 1k glTF component URLs via a constrained loader, and labels its source. The browser presents original source geometry separately from gameplay. Do not imply the historical model is a completed H01–H24 fantasy object.

The **frozen** mode is the verified archive created by tools/package_polyhaven_batch.py and .github/workflows/kilns-polyhaven-package.yml. All 20 unique source models for 24 object roles are downloaded exactly once per batch with size/MD5 checks. A GitHub Release retains one dated source archive for future reproduction; new source versions must be placed into a NEW release, not silently overwrite a saved composition. Neither mode downloads private visitor data or requires a Poly Haven login.

Source-only models can be hotlinked for an optional inspector; final in-scene gameplay should use reviewed and optimized local/hashed derivatives to prevent an upstream update from unexpectedly changing collision, scale, scene meaning or load time. The in-game live inspector passed a Chromium smoke test for H07 and its local proxy. Full 20-asset visual QA is still future work.
