Reauthorize if the token expires or access is revoked.
2. Keep all codebases meant to be editable under this repository (`worlds/*` and nested `worlds/elisium/kilns/*`) or explicitly authorize other repositories. Keep published source and manual as canonical Git history, rather than relying on ChatGPT conversation attachments to synchronize.

Previously approved GitHub connection does not guarantee that every future execution context exposes the same tools or authorizes unrestricted activities. Never paste a personal access token in chat.

Granting unlimited write permission does not guarantee changes will be correct, conflict-free or automatically occur between conversations. The user still needs to request work, or separately configure a supported automation/agent.

6. GitHub Pages serves the static site, not database, secret storage or OAuth credentials. Enable Pages in GitHub settings and configure deployment. Grant a narrowly scoped deployment action only when needed.

**Security:** avoid all-repositories permission if selected repositories suffice, never commit secrets, use protected branches and backups, and ensure asset redistribution rights. The user's desire for no repeated approvals cannot override application consent requirements or connection expirations.
