## KIL-LIGHT-001 — compositional field lighting
The ordinary Three.js sun shadow map is baked once at startup, then cached (no per-frame shadow redraw). A separate storm light direction is baked into the SAME allocation when entering/leaving storm mode. Moving characters and moving hoist groups do not participate in that static bake; they receive shadows. Cached shadows contain real roof/stair/iron geometry. A frozen moving-cable shadow may remain; dynamic object shadows are future work. Electric field is an approximate scalar irradiance volume sampled in world coordinates, computed from the existing fixture coordinates at startup, with simple deck occlusion. It is not a physically exact GI bake. The old point-light loop is removed when field mode mounts and restored on shader failure. Existing base lighting stays available with ?safe=1.

CloudBake generates a seeded 64×64×32 R8 Gaussian density volume, periodic in X/Z, with increasing density at higher slices. Integrate 16 optical-depth levels using exp(-tau), pack into a 4×4 264×264 R8 atlas with wrap gutters. Interpolate levels and translate periodic coordinates over a 64×96m artistic period. Shader projects receiver position along the shadow direction to an approximate roof plane, modulates direct diffuse/specular with transmission, and adds the precomputed lamp irradiance to diffuse. Ambient daylight changes separately. This is the fixed-direction approximation, not a real cloud/sun ray march or multi-patch GI solve. Light time is independent of Choir time; it must not create narrative facts or alter testimony.

Electric grid 48×96×16 R8, expanded to 200×392 atlas with gutters. Switch is binary; sun and ambient change continuously. Normal mode cycles day to dusk and back over 150s; fixed daylight and twilight selectable. Separate storm option uses more oblique sun vector for long, real architectural shadows, darker sky, one smooth lightning pulse with seeded variable spacing, a branching line above the skylight, delayed optionally enabled synthesized thunder, gentle intensity toggle with reduced-motion default. No rapid strobe, fullscreen white overlay, camera seizure or automatic loud sound. Dust shaft option is five batched additive sheets with cloud modulation and depth testing, not volumetric raymarching; no shadowing of the air itself, possible plane artifacts. User can disable it. Future: render correct volumetric shadows via sparse transfer basis or low-res froxel field if justified; temporal story events can later select a storm cue without altering knowledge state.

## Budget, in bytes
Density 131072; cloud atlas 69696; electric source 73728; electric atlas 78400. Sum retained CPU field arrays at initialization 352896 (344.625 KiB), GPU texel payload 148096 (~144.6 KiB). Excludes JS overhead, temporary bake allocation, renderer/driver overhead, meshes, original textures, shadow render target/depth attachment and optional audio (5s mono float buffer, ~0.92 MiB at 48kHz). Existing shadow map 2048², one allocation reused; its actual GPU cost is format/driver-dependent, e.g. 16 MiB for an RGBA8 color attachment plus depth. No second shadow atlas or per-frame cloud texture upload. Storm direction changes incur one shadow bake.

## Reproduce
From this directory: node test-light-field.mjs. Serve over HTTP. Select Sky → Storm, enable thunder if desired, allow ~15s first stroke. Add ?sky=storm or ?sky=twilight or ?safe=1, optional ?rays=1. For inspection: compare side-view roof haunch, gallery horizontal bands, hoist head, skylight footprint and storm wall shadow. Confirm no black screen, steady frame times, no flicker from texture streaming, and one shadow redraw per direction change.
